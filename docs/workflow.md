# 開発フロー(taskrail)

taskrail を導入したリポジトリでは、Issue がボードの列を左から右へ進みます。列は `flow::` ラベルで表します。
列を動かす(ラベルを付け替える)と、その列を担当するエージェントが自動で動きます。

```
Inbox → Spec → Plan → Ready → In Progress → Verify → Human Review → Done
```

## あなたがやること

| 場面 | 操作 |
| --- | --- |
| 作業を頼む | Issueテンプレート「タスク」で起票する |
| 仕様を承認する | Issue の仕様コメントを確認し、ラベルを `flow::plan` に変える |
| 計画を承認する | 計画コメントを確認し、ラベルを `flow::ready` に変える(`size::s` は自動) |
| AIの質問に答える | `blocked` の Issue にコメントで回答する(自動で再開します) |
| レビューする | PR を Approve してマージする。直してほしければ Request changes |
| やり直させる | ラベルを前の列に戻す(例: `flow::spec`) |

Ready から先は自動です。WIP上限に空きができると、古い Issue から順に着手されます。

## ラベル

| ラベル | 意味 |
| --- | --- |
| `flow::*` | 現在の列。1つの Issue に1つだけ |
| `blocked` | AIが質問を残して停止中 |
| `ai::ok` / `ai::no` | AIに実装を任せるか。認証・課金・マイグレーション・インフラは原則 `ai::no` |
| `size::s` / `m` / `l` | 規模。`l` は Plan 列で子Issueに分割する |

## 原則

- 仕様と計画の承認、マージは人間だけが行います。
- AIは迷ったら止まります。止まったら、答えるか、仕様を書き直してください。
- 同じ指摘を2回したら、ルールにします。優先順位は、linter やテストで強制 → レビューの観点に追加 → 規約に記載。
- 全体を止めるには、リポジトリ変数 `TASKRAIL_ENABLED` を `false` にします。

困ったときは [runbook.md](./runbook.md) を見てください。
