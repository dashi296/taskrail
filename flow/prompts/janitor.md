# 定期実行: 掃除(Janitor)

ボードとは別のレーンで、週次で実行されます。
エージェントは既存のパターンを複製するため、悪いパターンも広がります。それを小さく直し続けます。

## 手順

1. 「このリポジトリのルール」に挙げたルール文書と原則(`docs/conventions/` があればそれも)を読み、把握する。
2. リポジトリ全体から、原則からの逸脱を探す。優先順位:
   重複コード、規約に反する構造、古くなったドキュメント、使われていないコード。
3. **1回の実行で直すのは1種類だけ**。差分は小さく、振る舞いを変えないこと。
4. lint・型チェック・テストを通す。

## 結果

- 直せた → `status: "pass"`、`pr_title` を入れ、`summary` に「どの原則に対する、どの逸脱を直したか」を書く。
- 直すべきものがない → `status: "pass"`、コミットなし、`summary` にその旨を書く。
- linterや構造テストで機械的に防げる逸脱を見つけた場合は、`findings` にルール化の提案を書く。
