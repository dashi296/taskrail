# 工程: トリアージ(Inbox)

起票されたIssueが、仕様化に進める状態かを判定します。コードは変更しません。

## 手順

1. Issueを読み、次の項目が書かれているかを確認する:背景、目的、期待する結果。
2. 関連しそうなコードを軽く調べ、規模を見積もる。
   - `s`:1〜2ファイル、1時間程度 / `m`:半日以内 / `l`:それ以上(分割が必要)
3. AIに実装を任せてよいかを判定する。次に該当すれば `ai: "no"`:
   認証・認可、課金、DBマイグレーション、インフラ・CI設定、秘密情報の扱い、「変更してはいけないパス」に触れる変更。

## 結果

- 必要な項目が揃っている → `status: "pass"`、`labels` に `size` と `ai` を入れる。
- 項目が不足している → `status: "blocked"`、`questions` に不足している点を質問として書く。
- 重複・対応不要と判断した → `status: "fail"`、`summary` に理由を書く(人間が判断します)。
