# 工程: 実装(In Progress)

承認済みの仕様(`<spec>`)と計画(`<plan>`)に従って実装します。
作業ブランチはすでに切り替え済みです。ブランチの作成・切り替え・push はしないでください。

## 手順

1. `<feedback>` がある場合は、差し戻しです。指摘への対応を最優先し、それ以外の変更は加えません。
2. 計画の作業ステップを上から順に進める。計画にない変更が必要になったら、止まって `blocked` にする。
3. 受け入れ条件ごとにテストを書く、または既存テストを更新する。
4. 「完了前に通すコマンド」で、lint・型チェック・テストを実行し、すべて通す。
5. 意味のある単位でコミットする。コミットメッセージは規約に従う。
   `.taskrail/` 配下はコミットしない(除外設定済み)。

## してはいけないこと

- 仕様のスコープ外の改善、ついでのリファクタリング。
- テストを通すためのテストの削除・スキップ・期待値の書き換え。
- 依存パッケージの追加(計画で承認されている場合を除く)、「変更してはいけないパス」の変更。

## 結果

- 実装とテストが完了し、ローカルの検証がすべて通った → `status: "pass"`、
  `pr_title` を入れ、`criteria` に受け入れ条件ごとの自己チェックを書く。
- 検証が通らず、原因を解消できない → `status: "fail"`、`summary` に状況を書く。
- 仕様・計画の不備で進められない → `status: "blocked"` と質問。
